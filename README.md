# R1 NAS 屏幕面板

第一版已接入 NAS 实机，并以 Docker 双容器方式运行。文件级勒索行为监控暂不启用，第二版再做独立压力测试。

## 本地运行

```powershell
cd web
npm install
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。建议使用 376×960 的设备模拟尺寸。
开发服务器默认把 `/api` 代理到 `http://127.0.0.1:8080`。如果后端运行在 NAS 上，启动前将 `NAS_API_TARGET` 设置为 `http://NAS地址:8080`。

## 审核操作

- 首次打开显示“娴宝工作台”：女孩敲电脑，点击后回头指向电脑，电脑屏幕放大进入监控面板。
- 开场页显示真实用户名和使用状态；不返回文件名、路径、IP 或照片内容。
- 进入面板后，左上角“娴宝”按钮可以重新播放开场。
- 左右滑动切换总览、磁盘、系统页面，支持触摸、鼠标拖动和触控笔；当前页标题两侧也可点击切换。
- 滑动过程会跟随手指，并在首尾页提供阻尼反馈。
- 桌面浏览器可使用左右方向键。
- 底部不设置导航栏，完整空间用于展示监控数据。
- 左上角的“模拟断线”用于检查断线时保留旧数据和状态提示。
- 右下角“模拟勒索告警”用于审核红色全屏 WARNING；真实检测设计见 `SECURITY-DESIGN.md`。
- 磁盘页内容超过屏幕时，只在磁盘卡片区域内部滚动。
- 磁盘以“盘位 1 / 盘位 2 / 盘位 3”为主标识；点击卡片可展开系统设备路径。

可直接打开指定审核状态：

- `http://127.0.0.1:5173/`：Q 版开场。
- `http://127.0.0.1:5173/?intro=0&page=0`：总览页。
- `http://127.0.0.1:5173/?intro=0&page=1`：磁盘页。
- `http://127.0.0.1:5173/?intro=0&page=2`：系统页。
- `http://127.0.0.1:5173/?intro=0&threat=1`：疑似勒索行为红色告警。

## 实机 API

默认构建只使用真实接口。只有明确设置 `VITE_USE_MOCK=true` 时才启用演示数据，页面请求：

- `/api/status`
- `/api/disks`
- `/api/activity`
- `/api/health`
- `/api/security`（第一版返回“暂未启用”）

前端构建产物输出到 `server/static/`，供 Python 后端直接托管。

## Docker 部署

- 页面容器：`xianbao-r1-web`，局域网访问 `http://NAS地址:8080`
- 采集容器：`xianbao-r1-agent`，读取 DSM 主机状态并写入内部快照卷
- 显示容器：`xianbao-r1-display`，驱动海康威视 R1 内置屏幕与触摸模块
- 第一版不启动目录递归扫描，也不修改 DSM 的持久化 inotify 配置。

## 安装包

优先从 [GitHub Releases](https://github.com/chenle19/xianbao-r1-panel/releases) 下载 `.spk`，然后在 DSM 套件中心选择“手动安装”。第一次打开 `http://NAS地址:8080` 时，可以设置小女孩的名称。

> 兼容范围：仅在海康威视 R1（HIKSEMI / HS-AFS-R1、x86_64、Intel N100、Linux 5.10.55+）实测。其他带屏 NAS 不保证兼容。
